03 · Sessions in a stateless world

SEP-2567 session lifecycle RECORDED RUN

The 2026-07-28 spec made MCP stateless: per-request server factories behind load balancers, no shared storage. So issued handles are verified by deterministic derivation — a KSUID plus an HMAC tag — and any instance can tell an ID it issued from one it never did, with zero server-side state. Your four screening questions ANSWERED

Short versions here; the code is the long version.

Q2Workers fork after our queue thread has already started. What breaks, and how do you fix it?
The child inherits the queue's memory but none of its threads — the publisher is simply gone, so events enqueue forever and never send. Locks can also be inherited mid-held. We fix it twice over: an owner-PID check on every publish (works on 2.7, catches every fork however it happened) that rebuilds mutex, queue and workers under the new pid, and a Process._fork hook on 3.1+ that resets the child eagerly. Inherited unsent events are left to the parent, which still owns them — no double delivery. The recorded run forks twice and both children deliver 3/3.
Q3How do you guarantee an exception, a hung call, or a saturated queue never affects the tool response?
Structurally, not by convention. The request path touches exactly one AgentCat operation: a mutex-guarded array push that catches everything and returns. All hooks, redaction, truncation and network I/O run on worker threads — concurrently with the handler, adding no latency. Sockets get hard open/read timeouts; a full queue drops oldest by policy; shutdown drains within a bounded deadline and then re-raises the signal so the host can always die. The handler's own exceptions pass through untouched — we never eat a customer error.
Q4Have you worked with MCP or its Ruby SDK?
This preview is the answer: it attaches to MCP::Server from the official mcp gem, speaks tools/list and tools/call through real JSON-RPC dispatch, and implements SEP-2567 explicit handles for the stateless 2026-07-28 world — including the mint-back copy kept byte-for-byte, because your cross-SDK brief says agent-facing wording must not be reworded, and we read it.
Q1The gem we're most proud of, and its hardest API decision?
We'd rather show than tell — links and maintainership history come with the proposal, and the hardest decision in this codebase is already visible: making fault containment a structural property (one contained entry point on the request path) instead of sprinkling rescues, so the "never break the host" promise survives every future contributor.

The one line API SURFACE

Framework-agnostic: plain Ruby, Rails, Sinatra, Hanami — no framework dependency, nothing to configure to be safe.

# exactly the shape your TypeScript SDK promises require "mcp" require "agentcat" server = MCP::Server.new(name: "demo-weather-server") server.define_tool(name: "get_forecast", ...) { |city:| ... } AgentCat.track(server, project_id: "proj_x") # ← the line

Hooks — identify, resolve_session_id, redact_sensitive_information, redact_event, event_tags, event_properties — run off the request path. Two are live in this preview (identify, text redaction); the rest follow the same deferred, contained pattern.

What this preview is not

  • It is not the port. Exporters, the remaining hooks, diagnostics, the 77-file test-suite parity and CI across 2.7 → current are the contract — this is the proof that the hardest properties hold before you spend anything.
  • The simulations above mirror recorded runs — every number on this page (0.27 ms, 550 dropped, 3/3 per child, 27/27) comes from the run shown in section 05, not from imagination.
  • Sandbox note: the build environment had no rubygems.org access, so the official mcp gem loads from source and one dev-only dependency is satisfied by a small documented shim. On a normal machine, bundler uses the real gems.
  • Independent preview. Built from your public repositories, docs and the 2026-07-28 cross-SDK brief. Not affiliated with or endorsed by AgentCat; no AgentCat systems were touched — the collector here is a local test sink. The code is MIT and yours to keep whatever you decide.
